# Sauvegarde du bronze (plan Supabase Free : aucune sauvegarde automatique)

1. Poste de Rémy : WSL, `git clone https://github.com/RoJo69100/assistant-jeux` puis `cd assistant-jeux` ; Python 3.10+ (aucun paquet à installer pour la RPC).
2. Créer `.env` à la racine (ignoré par Git, jamais commité) avec ces NOMS : `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` et `BRONZE_EXPORT_TOKEN` (transport prioritaire, sans clé de service). Repli sessions cloud : `SUPABASE_SECRET_KEY` (via `sql_ro`), ou `SUPABASE_DB_URL_RO` (Postgres direct, facultatif).
3. Jeton d'export : le tirer au hasard sur le poste (`python3 -c "import secrets;print(secrets.token_urlsafe(32))"`), le mettre dans `.env`, enregistrer seulement son SHA-256 : `insert into bronze.export_tokens (token_sha256, label) values ('<sha256 hex>', 'poste-remy')` (éditeur SQL Supabase). Révoquer : `update bronze.export_tokens set revoked_at = now() where label = 'poste-remy'`. Table distincte du jeton d'ingestion.
4. Commande : `python -I pipelines/sauvegarde_bronze.py` (`--verifier-seulement` pour contrôler sans exporter). Elle lit la RPC `public.export_bronze` (lecture seule, `raw_pages` et `discord_messages` seulement, 5000 lignes et 3 Mo comprimés au plus par appel).
5. Fichiers : `~/backups/assistant-jeux/` (hors du dépôt, qui est public), un `.ndjson.gz` par table et par passage + `etat.json` (dernier id, total cumulé). Les passages suivants sont incrémentaux (id > dernier id). Premier passage du 16/11/2026 : `raw_pages` 53 Mo, `discord_messages` 16 Mo comprimés.
6. Contrôle : une ligne ✅/❌ par table compare le total sauvegardé au nombre de lignes d'id <= dernier id en base (le bronze est immuable).
7. Restauration (testée le 16/11/2026 sur 500 lignes par table : nombre de lignes et hachage MD5 des 11 colonnes identiques ; pas de restauration complète tant que la base est près de la limite de 500 Mo) : table cible créée par `sql/bronze/001` et `003`, puis par lots d'environ 1 Mo (`zcat f.ndjson.gz | jq -s -c .` donne le tableau JSON) : `insert into bronze.raw_pages overriding system value select * from jsonb_populate_recordset(null::bronze.raw_pages, '<tableau>'::jsonb);` (`overriding system value` est obligatoire : `id` est une colonne d'identité) ; à la fin, `select setval(pg_get_serial_sequence('bronze.raw_pages', 'id'), (select max(id) from bronze.raw_pages));`. Idem pour `bronze.discord_messages`.
8. Fréquence conseillée : hebdomadaire ; le rappel de début de session signale une sauvegarde de plus de 10 jours.
9. Le jeton et `SUPABASE_SECRET_KEY` ne se collent jamais dans un chat, un commit ou un fichier du dépôt. La clé publishable seule ne lit rien : `export_bronze` répond « jeton invalide » (HTTP 403) et les tables `bronze` ne sont pas exposées par l'API.
